# יגאל — אתר תדמית ודף נחיתה לתיאום פגישות

דף נחיתה בעברית (RTL מלא) עבור **יגאל**, שעוסק ב**תיאום פגישות בלבד** עבור סוכני ביטוח ובעלי רישיון בתחום הפיננסי והפנסיוני.

> **הבהרה מהותית שמנחה את כל תוכן האתר:** יגאל אינו מעניק ייעוץ, שיווק, המלצה פיננסית או המלצה פנסיונית. הייעוץ המקצועי ניתן על ידי בעל רישיון מתאים בלבד. אין באתר הבטחה לחיסכון, לתשואה, לשיפור תנאים או לתוצאה כלשהי. **כל שינוי טקסט עתידי חייב לשמור על העיקרון הזה.**

## מטרת האתר

לייצר לידים של אנשים המעוניינים לבדוק את מצבם הפנסיוני/הפיננסי, ולתאם עבורם פגישה עם בעל רישיון מתאים. הטופס כולל שאלות סינון מקדימות כדי שהשיחה והפגישה יהיו ממוקדות.

## מבנה האתר

| # | אזור | תיאור |
|---|------|-------|
| 1 | Hero | כותרת, הסבר קצר, שני כפתורי CTA וכרטיס "מה אני כן / לא עושה" |
| 1b | פס אמון | ארבע נקודות קצרות מתחת ל-Hero: משך המילוי, ללא עלות, בעל רישיון, פרטיות |
| 2 | למה לבדוק | שמונה כרטיסים: פנסיה, קרן השתלמות, גמל, ביטוחים, ריבוי מקומות עבודה, סדר במוצרים, בדיקה תקופתית, שאלות פתוחות + הבהרה |
| 3 | איך זה עובד | ארבעה שלבים + פאנל אמון ("מה חשוב שתדע מראש") |
| 4 | טופס לידים | **שם וטלפון חובה בלבד**, ואחריהם **אשף שאלות רשות — שאלה אחת בכל פעם** + Checkbox הסכמה (חובה) |
| 5 | שאלות נפוצות | שבע שאלות, כולן מבהירות את גבולות התפקיד |

| 7 | פוטר | ניווט, קישור להצהרת הנגישות, והבהרה משפטית מלאה |

בנוסף לדף הנחיתה יש שני עמודים משניים: `privacy.html` — הצהרת פרטיות, ו-`accessibility.html` — הצהרת נגישות. שניהם מקושרים מהפוטר בכל העמודים.

CTA מופיע בארבע נקודות: הדר, Hero, אמצע העמוד, וכפתור צף במובייל.

## מבנה הקבצים

```
.
├── index.html                  # כל תוכן האתר (עמוד יחיד)
├── privacy.html                # הצהרת פרטיות
├── accessibility.html          # הצהרת נגישות
├── assets/
│   ├── css/styles.css          # עיצוב: טוקנים → reset → פריסה → רכיבים → סקשנים → טפסים → רספונסיב → נגישות → שכבת ליטוש ואשף
│   ├── js/config.js            # תצורה פומבית (endpoint, הודעות) — ללא סודות
│   └── js/main.js              # UI, ולידציה, שליחת טפסים, אשף השאלות, אנימציות כניסה
├── docs/
│   └── google-apps-script.gs   # קוד צד-שרת לקליטת לידים (להדבקה ב-Apps Script)
└── README.md
```

אין תלויות, אין שלב build, אין framework. הפונט היחיד שנטען חיצונית הוא Assistant מ-Google Fonts.

## הרצה מקומית

האתר סטטי לחלוטין. אפשר פשוט לפתוח את `index.html` בדפדפן, אך מומלץ להריץ שרת מקומי:

```bash
# Python
python -m http.server 8000

# או Node
npx serve .
```

ואז לגלוש ל-<http://localhost:8000>.

### מצב הדגמה (DEMO)

כל עוד `leadEndpoint` ריק ב-`assets/js/config.js`, הטפסים עוברים ולידציה מלאה ומציגים הודעת הצלחה, **אך לא נשלחים לשום מקום** (הליד נרשם ל-console בלבד). זה מאפשר לבדוק את חוויית המשתמש לפני חיבור לשרת.

## חיבור הלידים ל-Google Sheets ול-Gmail

הארכיטקטורה מוכנה לחיבור, ללא צורך בשינוי קוד באתר עצמו:

1. צור Google Sheet חדש.
2. `Extensions → Apps Script`, והדבק את התוכן של `docs/google-apps-script.gs`.
3. עדכן בקובץ את `NOTIFY_EMAIL` לכתובת שאליה יגיעו ההתראות.
4. `Deploy → New deployment → Web app`:
   - **Execute as:** Me
   - **Who has access:** Anyone
5. העתק את כתובת ה-`/exec` שהתקבלה, והדבק אותה ב-`assets/js/config.js`:

```js
leadEndpoint: 'https://script.google.com/macros/s/XXXXX/exec',
```

מרגע זה כל שליחה נרשמת כשורה בגיליון ונשלחת אליך התראה במייל. הסקריפט יוצר את שורת הכותרת בעברית בעצמו בפעם הראשונה.

> ⚠️ **אם כבר קיים גיליון "Leads" מגרסה קודמת** — יש לשנות את שמו או למחוק אותו לפני החיבור. מבנה העמודות השתנה (חמש שאלות הכן/לא אוחדו לעמודה `situation`), ושורת הכותרת נוצרת רק כשהלשונית ריקה. אחרת השורות החדשות ייכתבו בעמודות שגויות בלי שום שגיאה.

### מבנה ה-payload

```jsonc
{
  "formType": "lead",            // או "contact"
  "submittedAt": "2026-08-28T09:00:00.000Z",
  "pageUrl": "https://…",
  // חובה
  "fullName": "…", "phone": "…", "consent": "כן",

  // רשות — עלולים להיעדר מה-payload לחלוטין
  "email": "…", "ageRange": "36–45",
  "topics": "פנסיה, ביטוחים",      // בחירה מרובה, מופרדת בפסיקים
  "situation": "יש לי קרן פנסיה פעילה, לא בטוח/ה מה יש לי",
  "lastReview": "לפני יותר משנה",
  "contactMethod": "WhatsApp", "contactTime": "גמיש",
  "notes": "…"
}
```

חלופות אפשריות ל-endpoint ללא שינוי בצד הלקוח: Make/Zapier Webhook, Formspree, או פונקציית Netlify/Vercel — כל שירות שמקבל `POST` עם גוף JSON.

## אבטחה ופרטיות

- **אין מפתחות API, סודות או טוקנים בקוד** — `config.js` מכיל רק כתובת endpoint פומבית והודעות תצוגה, וזה מתועד בראש הקובץ.
- כל האימות והשמירה מתבצעים בצד השרת (Apps Script), בחשבון Google של בעל האתר.
- הטופס **אינו מבקש** מספרי חשבון, פרטי אשראי, ת"ז או מסמכים, וגם הטקסטים באתר מבהירים שאין בהם צורך.
- שני הטפסים כוללים שדה **honeypot** נגד בוטים; מילוי שלו נראה למילוי כהצלחה, ובשרת הרשומה נדחית בשקט.
- לשליחה יש timeout (12 שניות כברירת מחדל) והודעות שגיאה נפרדות לתקלת רשת ולתקלת שרת.
- Checkbox ההסכמה הוא חובה, ומנוסח כאישור ליצירת קשר לצורך תיאום בלבד.

## הטופס — שדות חובה

הטופס מבקש **שם, טלפון ואישור הסכמה בלבד**. כל שאר השאלות הן רשות ומסומנות ככאלה.

הרציונל: יגאל מתאם שיחת סינון קצרה ואינו מוכר דבר בטופס, ולכן השיחה עצמה היא מנגנון הסינון. כל שאלת חובה נוספת חוסמת אנשים מלהשאיר טלפון בלי לחסוך זמן אמיתי. אם מסתבר שאיכות הלידים ירדה, ההמלצה היא להחזיר **שדה חובה אחד** — "מה חשוב לך לבדוק" — ולא יותר.

הוולידציה מונעת כולה מתכונת `data-rule` ב-HTML, ולכן **הפיכת שדה לחובה או לרשות היא עריכת HTML בלבד** ואינה דורשת שינוי ב-JavaScript.

## אשף השאלות (שאלה אחת בכל פעם)

שאלות הרשות אינן מוצגות כרשימה ארוכה אלא כאשף: **שאלה אחת על המסך בכל רגע**, עם פס התקדמות ומונה "שאלה X מתוך 7".

- **מעבר אוטומטי** — בשאלות בחירה יחידה (`data-advance="auto"`), בחירת תשובה מקדמת לשאלה הבאה אחרי 340ms. ההשהיה קיימת כדי שהמשתמש יראה מה סימן; במצב `prefers-reduced-motion` היא מתקצרת ל-60ms.
- **מעבר ידני** — בשאלות בחירה מרובה ובשדה החופשי (`data-advance="manual"`), כי לא ניתן לדעת מתי המשתמש סיים לסמן. המעבר נעשה בכפתור "המשך".
- **הכול רשות** — יש דילוג על שאלה בודדת ודילוג על כל השאלות בבת אחת.
- **מסך סיום** — בסופו מוצג סיכום התשובות שנבחרו, עם קישור לחזרה ולעריכה. אם דילגת על הכול מוצגת הודעה מרגיעה במקום סיכום ריק.

**עיקרון מימוש מרכזי:** כל השלבים נשארים ב-DOM ומוסתרים בעזרת התכונה `hidden` בלבד. `FormData` אוסף גם שדות מוסתרים, ולכן לוגיקת השליחה ומבנה ה-payload לא השתנו כלל. אין באשף אף שדה `data-rule`, ולכן הוא אינו יכול לחסום את שליחת הטופס.

**הוספת שאלה** היא הוספת `<div class="wiz-step" data-advance="auto|manual" hidden>` בתוך `#wizTrack` — הספירה, פס ההתקדמות והניווט מתעדכנים לבד. יש לעדכן את `aria-valuemax` ב-`#wizProgress` בהתאם.

## פרטיות

`privacy.html` היא הצהרת פרטיות מלאה: מה נאסף, למה, למי מועבר, משך שמירה (24 חודשים), אבטחה, עוגיות, זכויות עיון/תיקון/מחיקה וחזרה מהסכמה.

> ⚠️ **גם בעמוד הזה יש placeholders** — אימייל, טלפון ותאריך עדכון, מסומנים ב-`<mark>`. יש למלא אותם לפני פרסום.

ההצהרה מקושרת משלושה מקומות: הפוטר, הערת ההסכמה שמתחת ל-Checkbox בטופס, והתשובה ב-FAQ על מה קורה עם הפרטים. **בעת שינוי כלי העבודה (למשל מעבר מ-Google Sheets לשירות אחר) יש לעדכן את סעיף "למי המידע מועבר".**

## נגישות

- RTL מלא (`dir="rtl"`, `lang="he"`) ושימוש בתכונות לוגיות (`inset-inline`, `padding-inline`).
- מבנה כותרות היררכי, `skip-link`, ו-landmarks סמנטיים.
- קבוצות רדיו וצ'קבוקס עטופות ב-`role="radiogroup"`/`role="group"` עם `aria-labelledby`.
- הודעות שגיאה עם `role="alert"`, `aria-describedby` ו-`aria-invalid`, ומיקוד אוטומטי לשדה הראשון השגוי.
- `:focus-visible` בולט בכל אלמנט אינטראקטיבי; אזורי מגע במובייל ≥44px.
- תמיכה ב-`prefers-reduced-motion` וב-`prefers-contrast: more`.
- ניגודיות של 4.5:1 לפחות בטקסט רגיל, מעל הרקע הלבן וגם מעל `--bg-alt`. **בעת שינוי `--ink-mute` יש לבדוק מול שני הרקעים.**
- טקסט משני אינו יורד מתחת ל-14px.

### הצהרת נגישות

`accessibility.html` הוא עמוד הצהרת נגישות לפי ת"י 5568 / WCAG 2.0 AA, מקושר מהפוטר.

> ⚠️ **העמוד מכיל ארבעה placeholders** — שם רכז הנגישות, טלפון, אימייל ותאריך עדכון — מסומנים ב-`<mark>`. **חובה למלא אותם לפני פרסום**: הצהרת נגישות בלי דרך ליצור קשר עם רכז הנגישות אינה ממלאת את תפקידה.

## העלאה לאוויר

האתר סטטי, ולכן מתאים לכל אחסון סטטי:

- **GitHub Pages** — `Settings → Pages → Deploy from branch → main / root`. (כבר פעיל: https://igalromov.github.io/yigal-meeting-coordination/)
- **Netlify / Vercel / Cloudflare Pages** — גרירת התיקייה או חיבור ל-repo, ללא הגדרות build.

## התאמות נפוצות

| מה לשנות | איפה |
|----------|------|
| צבעים, רדיוסים, ריווחים | `:root` בראש `assets/css/styles.css` |
| טקסטים, שאלות, FAQ | `index.html` |
| הוספה/הסרה של שאלה באשף | `.wiz-step` בתוך `#wizTrack` ב-`index.html` |
| נוסח הצהרת הפרטיות | `privacy.html` |
| הפיכת שדה לחובה או לרשות | `data-rule` ו-`required` ב-`index.html` |
| פרטי רכז הנגישות | `accessibility.html` |
| כתובת שליחת הלידים | `leadEndpoint` ב-`assets/js/config.js` |
| הודעות שגיאה למשתמש | `messages` ב-`assets/js/config.js` |
| כללי ולידציה (טלפון/אימייל) | אובייקט `RULES` ב-`assets/js/main.js` |
| עמודות הגיליון והתראת המייל | `COLUMNS` / `HEADERS_HE` ב-`docs/google-apps-script.gs` |

בעת עריכת טקסטים — יש להקפיד שלא להשתמש בניסוחים שמהם משתמע ייעוץ, שיווק או המלצה מצד יגאל, ולא להבטיח חיסכון, תשואה או תוצאה.
